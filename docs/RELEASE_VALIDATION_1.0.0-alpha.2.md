# Release validation — 1.0.0-alpha.2

This record distinguishes automated checks from platform/distributor certification. Use the exact tagged source and the SHA-256 manifest attached to the release. Packages from the previous alpha are not reused.

## Source and privacy boundary

- The public checkout contains source, synthetic regression fixtures, public documentation, fonts and license notices.
- No manuscript, private Scrivener template, personal video, internal audit notes, local state, `node_modules` or intermediate executable from the development/test directory is copied into Git.
- Optional external-template tests require `PUBCRAFT_SCRIVENER_TEMPLATE_FIXTURE` and import a disposable copy. They are skipped by default; the normal Scrivener tests use generated/synthetic projects.
- Binary downloads are release assets, not Git-tracked files. Go release builds use `-trimpath`. Packaging uses newly allocated temporary staging directories and a defined resource list.

## Checks performed

### macOS Intel / x86_64

The release targets macOS 13 Ventura or newer. C/helper deployment targets and
the app's minimum-system-version metadata are set to 13.0, matching the Go binary's
minimum OS. Bundle display/build versions use Apple's numeric version fields;
the full alpha version remains in the UI, CLI and release metadata.

- Clean-checkout C/Go compilation, CLI integration suite, Go tests with the race detector and an explicit uncached `-count=1`, and `go vet`.
- The 15-runner browser regression suite passes in a dedicated Brave/CDP profile, including real PDF generation through the test adapter. This tests the adapter/browser renderer, not every normal headless-browser startup environment.
- `node --check` for the application and Watch scripts.
- Native CLI EPUB generation and GUI startup/state smoke tests with synthetic manuscripts and an isolated configuration.
- App assembled from current binaries/resources, ad-hoc signed after assembly and checked with `codesign --verify --deep --strict`.
- Portable-archive binary/font contents checked with `tests/check_packages.py`; DMG checksum checked with `hdiutil verify`.

The macOS installer is generated but is not silently installed over a user's applications during validation. The app is **not Developer ID signed or notarized**, and the PKG is unsigned. Valid ad-hoc signatures and DMG checksums are integrity checks, not Apple approval.

### Linux x64

The native [Release builds workflow](../.github/workflows/release-build.yml) uses an Ubuntu runner:

- Current C CLI compiled with musl and static linkage; native Go GUI build.
- CLI regression suite, uncached Go race tests and `go vet`.
- Native CLI/GUI smoke test; portable archive content verification and startup from its extracted files.
- DEB metadata/content inspection and startup from its extracted binaries.
- AppImage extraction and startup from the extracted CLI/GUI. This does not exhaustively test FUSE/desktop integration on all distributions.
- AppImage packaging tool and runtime downloads are checksum-pinned; a changed upstream payload fails the build rather than being accepted silently.

### Windows x64

The native Windows hosted-runner workflow builds the current C CLI with MinGW and the GUI with Go:

- CLI creation/export with a project path containing spaces; ZIP CRCs, required uncompressed first `mimetype` entry and XML parsing checked.
- The smoke manuscript includes invalid control/UTF-8 bytes and a four-space nested list, exercising the Windows archive backend and shared output sanitizer.
- GUI startup and `/api/state` verified with isolated home/configuration.
- Portable archive contents checked against current binaries/fonts, followed by smoke tests of extracted executables.
- NSIS installer built and silently installed in a disposable runner directory; installed CLI/GUI smoke-tested.

These are basic native smoke/installer checks, **not** the full browser/PDF suite on Windows or manual testing of every Windows edition. The installer is not publisher-signed.

## EPUBCheck

**EPUBCheck 5.4.0** is run with a temporary Java runtime against 14 synthetic EPUB cases generated by the clean macOS CLI:

- CLI-initialized book;
- quoted and literal-block UUIDs and an arbitrary legacy identifier;
- headings/fenced code and rich formatting, tables, lists, links, Unicode and typography settings;
- referenced nested images, a cover and an unused image;
- hostile XML-control/invalid-UTF-8 input;
- the six YAML parity fixtures shipped in `tests/fixtures/yaml`.

**Result: all 14 pass with zero errors and zero warnings.** This validates those generated books with the named checker version. It is not proof that every input produces a compliant ebook, nor Amazon KDP/IngramSpark/retailer certification. Always inspect the actual final book with the distributor's tools.

## Reproduction

```sh
make all
make check
go -C src/pubcraftgui test -race -count=1 .
go -C src/pubcraftgui vet ./...
node --check src/pubcraftgui/web/static/app.js
node --check src/pubcraftgui/web/static/watch.js
# Dedicated browser session required; see tests/README.md:
BROWSER_CDP_URL=http://127.0.0.1:9222 CHROMIUM_BIN="$PWD/tests/brave_render.sh" make check-browser
```

Go's cache does not track the external C binary, so use `-count=1` when that binary changes. Native package build commands and checks are captured in the release workflow. See its run history and the release's checksum file for the actual artifacts; failed preparatory workflow runs are not release approvals.

## Remaining limits

- Intel macOS, Linux x64 and Windows x64 packages only; no native Apple Silicon/Linux ARM release packages.
- No Apple notarization, Developer ID certificate or Windows publisher certificate is supplied by these automated builds.
- PDF appearance/startup depends on the installed renderer. Windows interactive PDF/browser coverage and broad Linux desktop/FUSE testing remain separate follow-up work.
- YAML is a supported subset in the C compiler. Unsupported UUID update forms fail without writing; this is intentional, not an assertion of full YAML compatibility.
- Native Windows CSPRNG/path/archive code is compiled and basic export/startup exercised in CI; this is not an exhaustive filesystem/security audit of Windows.
