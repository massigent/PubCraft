# Regression tests

Run `make check` from the repository root. It builds the current CLI/GUI, runs the
CLI integration tests (including installed fonts), then Go tests with `-race`.
PDF fixtures are generated by the tests; no previous `/tmp` audit files are needed.

Optional bounded fuzz run:

```sh
go -C src/pubcraftgui test -run '^$' -fuzz '^FuzzParsePDFData$' -fuzztime=3s -parallel=2
```

## Browser tests

The canonical browser test suite consists of 15 test runners:
1. `test_preview_geometry.cjs`: Preview panel geometry and layout stability.
2. `test_audit4_fixes.cjs`: Concurrency, rapid chapter switching, and cross-vault build isolation regressions.
3. `test_languages_preview.cjs`: UI localization (10 languages), RTL layout, Watch sync, and print settings.
4. `test_transitions_and_export.cjs`: Project switching safety (P0 identical files), export pre-flush (P1), and invalid folder rejection (P1 Politica A).
5. `test_project_safety.cjs`: Real new-book clicks from all three entry points, quoted-title reloads, YAML document markers/schema checks, locked structural actions, and stale-vault rejection.
6. `test_i18n_and_preview.cjs`: Manuscript print preview rendering and auto language detection.
7. `test_publication_preview.cjs`: Manual publication preview (Option A), zero builds on open/type/interaction, pre-build flush, isolated preview artifacts, PDF.js byte rendering, facing spreads, and guide overlays.
8. `test_editor_toolbar.cjs`: Minimalist formatting toolbar (bold, italic, H2, H3, blockquote, lists, scene break, link), native shortcuts (Cmd+B, Cmd+I, Cmd+K), image upload into `images/`, clipboard paste, and auto-save.
9. `test_welcome_and_recents.cjs`: Welcome launcher screen, 10-language localized UI, tutorial & keyboard shortcuts modal, 1-click recent books opening, book close return, workspace folder management, and file browser quick access.
10. `test_notebook_and_title.cjs`: Book notebook drawer, in-place title rename, autosave queue with slow network resistance, conflict detection, and note-to-chapter conversion.
11. `test_focus_mode.cjs`: Distraction-free full-screen writing mode (F11/Esc), typewriter centered scrolling, and dimming modes.
12. `test_dark_mode.cjs`: Dark mode theme switching, persistence, contrast checks, and modal styling.
13. `test_topbar_responsiveness.cjs`: Topbar and docbar responsiveness across breakpoints, unified dropdowns, and compact layouts.
14. `test_line_breaks.cjs`: Single line breaks preserved as visual paragraphs in book preview rendering.
15. `test_residual_selection.cjs`: Selecting/importing Markdown files in a folder that is already a book preserves chapters, IDs, titles, order and custom metadata; invalid `book.yaml` is rejected byte-for-byte.

Execute via either Makefile or npm:

```sh
# Via Makefile (rebuilds binaries automatically before running tests):
npm install --prefix tests
BROWSER_CDP_URL=http://127.0.0.1:9222 make check-browser

# Or directly via npm inside tests/:
cd tests && npm test
```

> **IMPORTANT**: The GUI binary (`build/pubcraftgui`) MUST be recompiled whenever frontend assets in `src/pubcraftgui/web/` are modified, as web files are embedded into the Go executable via `go:embed`. `make check-browser` ensures `all` is built before running the test scripts.

### Prerequisites

Start Brave/Chromium with remote debugging on port 9222 on a **dedicated profile** first:
```sh
/Applications/Brave\ Browser.app/Contents/MacOS/Brave\ Browser --remote-debugging-port=9222 --user-data-dir=/tmp/brave-test-profile &
```
The tests connect via Chrome DevTools Protocol (CDP), create and close isolated browser contexts and temporary vaults, and never close the main browser. The HTTP server binds a temporary loopback port without opening a system browser tab.
`PUPPETEER_MODULE` can point to an existing `puppeteer-core` installation if not installed locally in `tests/node_modules`.

To include real PDF rendering through that CDP session:

```sh
CHROMIUM_BIN="$PWD/tests/brave_render.sh" make check-browser
```

The adapter is test-only. It tests the real browser renderer, PDF.js, dimensions,
Watch regeneration and external output, but not normal headless process startup.
Without `CHROMIUM_BIN`, PDF browser tests are explicitly skipped.

## Packaging

`make pkg-macos` rebuilds the native bundle, DMG, PKG and portable archive.
Font resources are installed beside the CLI or under `share/pubcraft/fonts`.
`PUBCRAFT_FONTS_DIR` can override that lookup for custom deployments.

Linux/Windows require current **C binaries**, not just cross-compiled Go GUIs.
Packaging refuses a C binary older than `src/pubcraft.c`; build it using the target
toolchain (Linux compiler or MinGW), then run the corresponding `make pkg-*` target.
Native release jobs in `.github/workflows/release-build.yml` build and test the
Linux/Windows packages. Linux packaging uses `scripts/package_release.py linux`
with `dpkg-deb` and checksum-verified `APPIMAGETOOL` / `APPIMAGE_RUNTIME` paths;
Windows uses `scripts/package_release.py windows` with native NSIS on PATH.
These packages cannot be certified merely by building the macOS application.

Check portable archives before publishing:

```sh
python3 tests/check_packages.py "build/PubCraft-$(cat VERSION)-macos.tar.gz"
make verify-packages  # checks all three portable archives; old ones must fail
```

Do not publish older installers left in `build/` as if they contained the fixes.
`make` rebuilds standalone binaries, not an existing macOS app: run `make app`
to update `build/PubCraft.app`. To test the bundle's embedded GUI directly:

```sh
PUBCRAFT_GUI_BIN="$PWD/build/PubCraft.app/Contents/MacOS/pubcraftgui" node tests/test_project_safety.cjs
```

Release-specific results and limitations are recorded in
[`docs/RELEASE_VALIDATION_1.0.0-alpha.3.md`](../docs/RELEASE_VALIDATION_1.0.0-alpha.3.md).
Mac release outputs are always Universal 2. Read [AGENTS.md](../AGENTS.md) and
[the release playbook](../docs/RELEASING.md) before packaging or publishing.
`make verify-macos-release` checks all four Mac formats and both CPU slices;
the workflow then runs the exact same artifacts natively on Intel and Apple Silicon.
Portable guard tests: `python3 -m unittest discover -s tests -p test_release_guards.py`.
Always run `go -C src/pubcraftgui test -race -count=1 .` when the C binary changes:
Go's test cache does not track that external executable.

Two additional real-template tests are opt-in through
`PUBCRAFT_SCRIVENER_TEMPLATE_FIXTURE`. They copy the selected file into a temporary
directory before importing it. No private template is shipped or read by default;
the normal Scrivener tests use synthetic projects.

Project mutations require the `X-PubCraft-Vault` header. The server serializes
these mutations with saves, builds and project transitions, rejecting missing or
stale project contexts with HTTP 409. The application supplies this header;
external API clients must do the same.

## Implementation boundaries

Saving uses the content version returned by `/api/chapter` as `base_version`.
A stale version receives HTTP 409; a missing version receives HTTP 428. Client-local
edit counters are only for dirty state, not server-side concurrency control.

Successful print settings are stored atomically in `.pubcraft-print.json` in the
vault. Watch retains trim, bleed and external destination across reload/restart;
user `book.yaml` is not rewritten by exporting.

The PDF reader supports the unencrypted classic and Flate xref/object streams used
by the supported renderers, including PNG predictors and TIFF predictor at 8 bits.
It checks page-tree counts/cycles, bounds and decoding limits. Unsupported filters
fail explicitly. It is **not** a complete ISO 32000 implementation or a certification
of KDP compliance. Keep independent PDF/rendering checks in release validation.
